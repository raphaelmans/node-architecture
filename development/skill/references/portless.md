# Portless Integration

Read the foundations contract and selected runtime mapping. Resolve installation, runtime compatibility, machine effects, child environment, naming/worktrees, script delegation, and shutdown using [official Portless documentation/source](https://github.com/vercel-labs/portless#readme) matching the installed or selected release. Derive syntax at execution time.

Install and wire necessary tooling within existing authorization and package-manager policy. Preserve a direct command and prevent recursive wrappers. Keep package task ownership and existing workspace orchestration; consult [Turborepo development](https://turborepo.dev/docs/crafting-your-repository/developing-applications) and [environment guidance](https://turborepo.dev/docs/crafting-your-repository/using-environment-variables) when detected. Development tasks are non-cached, with long-running lifecycle where applicable. Resolve environment filtering where values are actually injected.

Distinguish the assigned internal listening port from the external origin. Verify the runtime consumes the port. Map the resolved self-origin to an existing application variable only when needed, in development tooling after the child environment exists and before app startup. Application schemas/source never need Portless-specific values. Preserve arguments, environment, signals, exit status, and direct-start origin behavior.

For multiple apps, resolve each identity and supply existing peer-origin settings from authoritative resolution or an explicit verified project mapping. Do not derive a peer URL by replacing part of the caller's hostname. Resolve peer targets before consumers capture configuration; preserve readiness handling. A filtered start must report missing required peers rather than connect to another checkout. URLs do not isolate backing databases or queues.

Preserve the chosen direct cross-origin or same-origin proxy arrangement. Check CORS/cookies against the actual frontend and, for proxy forwarding, upstream Host routing and TLS trust. Do not bypass certificate or trusted-proxy validation.

Verify two concurrent application sets and actual same-checkout frontend/API requests, plus activated callback, streaming, or WebSocket behavior. Preserve shared machine proxy state when stopping test-owned processes/routes.
