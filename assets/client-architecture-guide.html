RULE / 01

Render, do not transport

Components render state and submit intent through feature-specific query adapters.

RULE / 02

Cache has one owner

Query adapters own invalidation, optimistic state, and server-state lifecycle through stable shared keys.

RULE / 03

Validate at boundaries

Feature APIs parse wire responses and map transport data into feature-facing results.

RULE / 04

Lifecycle is explicit

Factories build heavy infrastructure once; the composition root owns its lifetime.

Owner / 02

Query adapter

Owns mutation status, success analytics, and cache synchronization. Analytics failure remains non-fatal behind its port.

features/users/hooks.ts
useCreateUser
export function useCreateUser() {
  const queryClient = useQueryClient();
  const analytics = useProductAnalytics();
  const userApi = getUserApi();

  return useMutation({
    mutationFn: (input: CreateUserInput) => userApi.create(input),
    onSuccess: async (user) => {
      analytics.track({
        name: "user_created",
        properties: { source: "settings" },
      });

      queryClient.setQueryData(userKeys.detail(user.id), user);
      await queryClient.invalidateQueries({
        queryKey: userKeys.lists(),
      });
    },
  });
}
Owner / 03

Feature API

Owns the endpoint contract, parses untrusted data, maps the DTO, and reports only schema failures owned by this boundary.

features/users/api.ts
UserApi + factory
export interface IUserApi {
  create(input: CreateUserInput): Promise<User>;
}

export class UserApi implements IUserApi {
  constructor(private readonly deps: UserApiDeps) {}

  async create(input: CreateUserInput): Promise<User> {
    const request = CreateUserInputSchema.parse(input);

    try {
      const raw = await this.deps.clientApi.post<unknown>(
        "/api/users",
        request,
      );
      return toUser(CreateUserResponseSchema.parse(raw));
    } catch (error) {
      if (error instanceof ZodError) {
        this.deps.logger.error({
          eventName: "user.create.response.invalid",
          attributes: { "error.type": "api.invalid_response" },
          error,
        }, "Create user response violated contract");
        throw invalidResponseError(error);
      }
      throw this.deps.toAppError(error);
    }
  }
}

export const createUserApi = (deps: UserApiDeps): IUserApi =>
  new UserApi(deps);
Owner / 04

Client API

Contains Ky construction and shared transport policy. Its implementation decodes the envelope, correlates, logs once, and returns only payload data.

common/clients/client-api.ts
createClientApi
export function createClientApi(deps: ClientApiDeps): IClientApi {
  const transport = ky.create({
    baseUrl: deps.baseUrl,
    timeout: deps.timeoutMs ?? 30_000,
    throwHttpErrors: false,
  });

  return new KyClientApi({
    transport,
    logger: deps.logger.child("http"),
  });
}

// KyClientApi.post owns the shared transport sequence:
// request ID → POST → envelope decode → one outcome log → data.
Owner / 05

Composition root

Creates vendors and infrastructure once, wires focused dependencies, and exposes only the feature API accessor used upstream.

common/runtime/browser.ts
Browser runtime wiring
export function createBrowserRuntime(config: BrowserRuntimeConfig) {
  const logger = createAppLogger(config.logging);
  const analytics = createProductAnalytics({
    ...config.analytics,
    logger,
  });
  const clientApi = createClientApi({
    baseUrl: config.apiBaseUrl,
    logger,
  });
  const userApi = createUserApi({
    clientApi,
    logger: logger.child("user:api"),
    toAppError,
  });

  return { logger, analytics, clientApi, userApi };
}

let runtime: ReturnType<typeof createBrowserRuntime> | undefined;

export const getUserApi = (): IUserApi =>
  (runtime ??= createBrowserRuntime(readPublicRuntimeConfig())).userApi;

TanStack Query / 04

Keys describe identity. Adapters own lifecycle.

Query keys are centralized, hierarchical, serializable, and specific enough to target cache work without coupling components to cache mechanics.

Strategy

Match the adapter

Direct tRPC uses generated utilities; wrapped tRPC uses matching internal keys; REST and fetch use plain key factories.

useUtils · buildTrpcQueryKey · userKeys
  • One strategy per adapter path
  • Preserve tRPC cache interop
  • Keep every key serializable
Ownership

Shared key registry

Reusable feature-specific keys live under common so query/cache-sync adapters can coordinate without importing feature internals.

common/query-keys/users.ts
  • No inline keys in components
  • Normalize only domain-equivalent inputs
  • Keep query functions out of key files
Invalidation

Narrowest stable scope

Invalidate or patch only what the successful operation made stale.

invalidateQueries({ queryKey: userKeys.lists() })
  • Batch related invalidations
  • Set detail data when returned
  • Avoid invalidating the entire cache
Canonical non-tRPC query key factory
export const userKeys = {
  all: ["users"] as const,
  lists: () => [...userKeys.all, "list"] as const,
  list: (filters: UserListFilters) => [...userKeys.lists(), normalizeFilters(filters)] as const,
  details: () => [...userKeys.all, "detail"] as const,
  detail: (userId: string) => [...userKeys.details(), userId] as const,
};

Mutation ownership

Pick one invalidation owner.

Hooks are the preferred default. Component coordination is allowed when a screen combines independent feature workflows and makes the broader decision.

Telemetry boundaries / 05

Related signals. Separate contracts.

Operational logs explain runtime behavior. Product analytics explains user behavior. Error reporting receives selected failures through an adapter. None becomes a general telemetry service locator.

Injected port

AppLogger

OpenTelemetry-shaped structured operational events for local debugging and production diagnosis.

  • debug namespaces in the browser
  • Optional filtered Sentry log sink
  • One failure owner; redact before fan-out
Separate typed port

Product Analytics

Typed events describing meaningful user and product outcomes after success.

  • Consent gates capture
  • Identify and reset stay explicit
  • Critical durable events originate server-side
Adapter destination

Error Reporting

Sentry receives selected handled failures from the owning boundary and unhandled failures from the error boundary.

  • Not every log is an exception
  • No blanket QueryClient reporting
  • Transport and schema errors retain safe metadata
Ambient runtime context

Correlation

Request and trace identifiers enrich operational records without entering business DTOs or feature method signatures.

  • Client API owns request IDs
  • Standard trace headers cross the network
  • Context never becomes a dependency bag
DebuggingLog

user.create.failed with level, timestamp, request ID, error kind, and safe attributes.

Product insightTrack

user_created after confirmed success with a typed, low-cardinality event schema.

IncidentReport

An actionable exception with stack, release, environment, and scrubbed diagnostic context.

CorrelationTrace

Connect browser work to server handling without manually threading context through every call.

export function createClientRuntime(config: ClientRuntimeConfig) {
  const logger = createAppLogger(config.logging);
  const analytics = createProductAnalytics(config.analytics);
  const clientApi = createClientApi({ baseUrl: config.baseUrl, logger });
  const userApi = createUserApi({ clientApi, logger });
