Four invariants

RULE / 01

Adapter calls controller

Every public framework adapter resolves one portable capability controller.

RULE / 02

Controller calls one

It selects one service or one use case and owns public-boundary mapping.

RULE / 03

Ports face inward

Application code depends on interfaces. Concrete SDKs and frameworks remain adapters.

RULE / 04

Contracts are explicit

Zod wire contracts are shared. ORM entities never become public DTOs by accident.

Layer explorer / 02

Every layer owns one kind of decision.

Select a layer to inspect its contract. The separation exists so that business behavior can be tested without a framework, database, or vendor.

Choose a layer
FA
Framework edge

Framework Adapter

Translate an untrusted framework request into one controller call, then serialize its validated public response.

Owns

Parsing, Zod validation, authentication, authorization, rate limiting, envelopes, and central error mapping.

Calls

Exactly one factory-created framework-neutral controller. Routes never resolve inner layers directly.

Do
  • Establish request observability scope
  • Validate both input and public response
  • Map AppError.kind centrally
Do not
  • Map commands or domain results
  • Call services or use cases
  • Import ORM entities
CT
Portable inbound boundary

Controller

Map one public capability using plain TypeScript so Next.js, Express, Hono, tRPC, OpenAPI, or Nest can reuse it unchanged.

Owns

Shared-input to command mapping, plain actor mapping, null-to-domain-error decisions, and internal-result to shared-response mapping.

Calls

Exactly one service for a single-domain capability or one use case for orchestration.

Do
  • Depend on service/use-case interfaces
  • Return shared response shapes
  • Stay independently unit-testable
Do not
  • Import Request, NextResponse, or tRPC types
  • Choose HTTP status or envelopes
  • Receive tracing or transaction context
UC
Application layer

Use Case

Own a business workflow that crosses service boundaries or coordinates transactional work with post-commit effects.

Owns

Multi-service orchestration, transaction boundaries, sequencing, compensations, outbox enqueue, and application outcomes.

Depends on

Service interfaces, TransactionManager, and only the separate ports it uses such as AppLogger or ProductAnalytics.

Do
  • Keep external effects after commit or in an outbox
  • Pass { tx } to participating services
  • Test ordering at the workflow boundary
Do not
  • Parse HTTP or tRPC types
  • Reach directly into a database
  • Become a bag of unrelated domain rules
SV
Domain policy

Service

Express single-domain behavior and invariants independently from transports, ORM clients, and vendor SDKs.

Owns

Business rules, domain error decisions, entity transformations, and transactions for self-contained writes.

Transaction mode

Participates when options.tx is supplied; otherwise a write service may open its own transaction.

Do
  • Depend on repository/provider interfaces
  • Throw typed domain errors
  • Log only significant business events
Do not
  • Call another service to orchestrate a workflow
  • Import Next.js or tRPC
  • Know serialization envelopes
DB
Persistence boundary

Repository

Hide database access behind a module-owned interface and return internal entities, not public API shapes.

Owns

Queries, persistence semantics, ORM mapping, null behavior, and translation of known constraint failures.

Transaction mode

Selects the supplied transaction client or the base database client. It never starts a transaction.

Do
  • Accept optional TransactionOptions
  • Implement an application-facing port
  • Test query and transaction semantics
Do not
  • Own business workflows
  • Return HTTP response DTOs
  • Log routine failures at every layer
PX
External boundary

Provider

Adapt email, storage, auth, payments, queues, or analytics vendors to a stable application port.

Owns

Credentials, SDK types, vendor payload mapping, retry/idempotency mechanics, and provider-specific failures.

Testing

Fixture-backed contract tests protect the boundary. Domain unit tests receive a fake or stub port.

Do
  • Translate vendor data at the edge
  • Keep adapters replaceable
  • Sanitize failures before public mapping
Do not
  • Leak SDK types into services
  • Store credentials in application code
  • Mix unrelated telemetry capabilities
K0
Stable core

Kernel

Hold small, framework-agnostic contracts used across modules and implemented by outer infrastructure.

Contains

AppError, response primitives, TransactionManager, AppLogger, ProductAnalytics, auth types, and pagination.

Import rule

Browser-safe, side-effect-free primitives only. No module, framework, database, Node.js API, environment, or vendor dependency.

Do
  • Keep ports minimal and stable
  • Use opaque infrastructure handles
  • Let runtime adapters implement ports
Do not
  • Turn it into a utility dumping ground
  • Import concrete Pino or Drizzle types
  • Let the kernel know modules

Boundary discipline / 04

Similar concerns. Separate channels.

Correlation, transactions, server logs, analytics, and contracts travel differently because they answer different questions.

Ambient async scope

Observability Context

Established once at the transport or worker boundary and read by runtime adapters.

  • requestId identifies one handling attempt
  • traceId connects distributed work
  • Never passed through controller/service method parameters
Explicit method option

Transaction Context

An opaque handle to one active database transaction. It exists only to preserve atomic database work.

  • Passed as TransactionOptions { tx? }
  • Owned by a service or orchestration use case
  • Contains no logger, auth, request, or trace fields
Injected port

AppLogger

Operational server logging for debugging and runtime behavior. Pino is an adapter, not the application contract.

  • Injected only where operational logs are emitted
  • Adapter enriches from active observability scope
  • Repositories normally do not log
Separate injected port

Product Analytics

Typed user and business behavior events delivered through vendor adapters.

  • Composite adapter may fan out to multiple vendors
  • Important events use an outbox
  • Never merged into a telemetry service locator

  });
}

// 1. modules/user/controllers/get-user.controller.ts — plain TypeScript
export class GetUserController {
  constructor(private readonly users: IUserService) {}

  async execute(input: GetUserInput, actor: Actor): Promise<GetUserResponse> {
    const user = await this.users.findVisibleById(input.id, actor);
    if (!user) throw new UserNotFoundError(input.id);
    return {
      id: user.id, email: user.email, name: user.name,
      createdAt: user.createdAt.toISOString(),
    };
  }
}

// 2. modules/user/services/user.service.ts — single-domain policy
export class UserService implements IUserService {
  constructor(private readonly users: IUserRepository) {}

  async findVisibleById(id: string, actor: Actor): Promise<User | null> {
    const user = await this.users.findById(id);
    return user && canViewUser(actor, user) ? user : null;
  }
}

// 3. modules/user/repositories/user.repository.ts — persistence only
export class UserRepository implements IUserRepository {
  constructor(private readonly db: DbClient) {}

  async findById(id: string): Promise<User | null> {
    const [row] = await this.db.select().from(users).where(eq(users.id, id)).limit(1);
    return row ?? null;
  }
}

// 4. modules/user/factories/get-user.factory.ts — composition root
let userService: IUserService | undefined;

function makeUserService(): IUserService {
  return userService ??= new UserService(
    new UserRepository(getContainer().db),
  );
}

export function makeGetUserController(): IGetUserController {
  return new GetUserController(makeUserService());
}
Only extraction, authentication plumbing, response construction, and central error integration vary. The controller, service, repository, factory, and their tests remain unchanged.

Test-double policy

Prefer the least theatrical double.

Tests stay deterministic and offline. Strict internal interaction assertions are reserved for cases where ordering is the behavior.

Default orderFixture → fake → stub

Representative data and simple working boundaries keep tests readable and resilient.

Escalate only
Interaction proofSpy → mock

Use spies for meaningful calls. Use strict mocks only when the exact interaction is itself contractual.

When tRPC and OpenAPI expose the same capability, parity tests are required for input validation, business outcomes, error codes, authentication, and rate limiting.
